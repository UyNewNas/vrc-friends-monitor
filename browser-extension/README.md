# VRC 好友监控 · 浏览器扩展

这是本项目的主要客户端，采用 Chromium Manifest V3，适用于 Chrome / Edge 120 及以上版本。目前通过「加载已解压的扩展程序」安装，尚未发布到浏览器扩展商店。

扩展通过同一浏览器配置文件中已打开的 VRChat 官网标签页，定时同步好友状态。请保留至少一个官网 `/home` 页面；它可以放在后台。账号密码、验证码都在官网输入。扩展界面不收集密码，也不读取、导出或复制登录 Cookie。

## 0.1.2 通知修复与更新

0.1.2 修复了正常连接时手动「立即同步」只更新状态基准、未生成变化记录与通知的问题。现在监控启用、连接正常且基准未过期时，手动和定时同步使用相同的变化检测；下一次同步不会重复提醒。首次同步、暂停期间手动查看、账号切换及中断恢复仍静默建立基准。

弹窗和完整面板新增「发送测试通知」，无需等待好友上下线；它不会请求 VRChat、开启监控、改变好友规则或写入动态记录。通知区显示提醒好友数量和最近一次发送结果，并在后续发送成功时清除旧的失败提示。排查步骤见下方[通知排查与测试](#通知排查与测试)。

0.1.0 从扩展后台直接请求接口，可能在官网已经登录时仍收到 HTTP 403。0.1.1 改为通过官网页面内的隔离脚本发送正常的同源请求，让浏览器在官网上下文中处理会话。扩展不读取或搬运认证 Cookie，不伪造请求头，也不跟随跨域接口跳转。

如果已经安装旧版：

1. 用新版文件覆盖原扩展目录，在扩展管理页点击「重新加载」，确认版本为 **0.1.2**。沿用原安装目录即可保留该扩展的本地规则和记录。
2. **刷新此前已经登录的 VRChat 官网标签页一次，并保留该标签页。** 静态内容脚本需要新的页面加载才能生效；仅刷新扩展不够。
3. 回到扩展点击「立即同步」。缺少官网页面或脚本时不会发出 API 请求，页面就绪后可以立即再试；真实 HTTP 限流和 `Retry-After` 仍需等待。

连接错误现在区分官网未打开、页面需要刷新、页面无响应、登录失效及 HTTP 状态。状态数组中个别好友暂时未分类或分类冲突时，该好友显示「未知」，不会导致全部好友同步失败，也不会产生虚假上下线通知。

## 安装与第一次使用

1. 获取当前分支的源代码，或下载该分支已通过 CI 的扩展 ZIP 包。
2. 如果使用源代码，安装目录是仓库中的 `browser-extension`。如果使用 `VRC-Friends-Monitor-*-chromium.zip`，先解压，安装目录是直接包含 `manifest.json` 的文件夹。
3. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`，开启「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择上一步的安装目录。不要选择仓库最外层目录，也不要直接选择 ZIP 文件。
5. 在这个浏览器、这个用户配置文件中打开 [VRChat 官网](https://vrchat.com/home)，正常登录并完成官网要求的验证。如果官网在安装前已经打开，请刷新官网一次；之后保留这个标签页。
6. 点击工具栏的扩展图标，再点击「打开完整面板」。若显示需要登录，完成官网登录后点击「立即同步」。
7. 在好友列表里为需要关注的人勾选「上线」和 / 或「离线」，确认「桌面通知」已打开，并允许系统显示浏览器通知。
8. 点击「发送测试通知」，检查浏览器是否接受请求及系统是否显示横幅。尚未同步账号时也可以先测试通知通道。

初次成功同步用于建立状态基准，不会把当前在线的全部好友报成「刚上线」。随后在正常定时或手动同步中检测到的游戏状态变化才会记入动态记录，并按你勾选的规则提醒。

使用源代码安装无需 Node.js，也无需运行构建命令。请保留安装目录；浏览器会继续从这个目录加载文件。更新源代码或替换解压内容后，到扩展管理页点击该扩展的「重新加载」，再刷新官网标签页一次。

### 获取并核对 CI 安装包

在仓库 GitHub Actions 中打开对应提交的 **Browser extension** 工作流，确认扩展检查与 Windows 兼容性检查通过，再下载 `vrc-friends-monitor-chromium` artifact。GitHub 下载的 artifact 外层 ZIP 中包含扩展 ZIP 及其 `.sha256` 文件；将外层 ZIP 解压后，再解压其中的扩展 ZIP 用于安装。

安装前可核对 `.sha256` 文件中的摘要。Windows PowerShell 示例：

```powershell
Get-FileHash .\VRC-Friends-Monitor-0.1.2-chromium.zip -Algorithm SHA256
Get-Content .\VRC-Friends-Monitor-0.1.2-chromium.zip.sha256
```

两处 SHA-256 应一致。文件名中的版本号以实际下载内容为准。摘要用于核对文件是否改变；来源仍应是你选定的仓库、分支和提交。

## 监控行为

| 项目 | 当前行为 |
| --- | --- |
| 状态同步 | 默认每 1 分钟；完整面板可改为每 2 或 5 分钟 |
| 好友昵称目录 | 首次同步时加载，之后约每 10 分钟刷新 |
| 游戏在线 | 好友当前处于 VRChat 游戏在线状态 |
| 未知 | 官网暂时未能确定该好友的分类；不会据此产生上下线记录 |
| 网站活跃 | 官网报告的非游戏客户端活跃状态（例如网站），单独显示，不计作游戏上线 |
| 游戏上线提醒 | 从非游戏在线变为游戏在线时，按好友的「上线」规则通知 |
| 游戏离线提醒 | 从游戏在线变为非游戏在线时，按好友的「离线」规则通知；好友此时仍可能显示网站活跃 |
| 动态记录 | 正常同步时记录检测到的游戏上下线变化；每个账号最多保留最近 1,000 条 |
| 立即同步 | 监控启用且基准有效时同样记录变化、按规则通知；受 30 秒节流与服务器等待时间约束 |
| 发送测试通知 | 使用同一浏览器通知通道试发固定消息；独立于账号、监控开关及好友提醒规则 |
| 暂停监控 | 点击「暂停监控」后停止自动请求，仍可手动同步；点击「开启监控」后重新建立基准 |
| 账号切换 | 以官网下一次成功同步识别的账号为准；好友规则和历史记录按账号分开 |

动态记录的时间是扩展**检测到变化的时间**。它不是 VRChat 提供的精确登录或退出时间；两次同步之间短暂上线又离线的变化可能被漏过。

首次同步、暂停期间手动查看、重新登录、账号切换，以及断线或较长延迟后的恢复同步，会更新状态基准，不会补报期间的上下线变化。这样可避免恢复后一次性弹出旧通知。好友新增、删除也不会伪装成游戏上下线事件。

关闭扩展弹出窗口或完整面板后，仍可按计划同步，**但需要保留至少一个已登录的 VRChat 官网标签页**。关闭官网、页面被浏览器冻结或丢弃后，扩展会保留旧结果并标记待更新；重新打开或激活官网页面后可恢复。**浏览器完全退出后无法监控；电脑休眠、断网、浏览器节能或后台调度延迟都可能造成空档。** 官网会话也可能过期，需要回官网重新登录。浏览器扩展改善了登录入口与后台恢复方式，不提供永久在线或实时无遗漏的保证。

## 连接异常时

| 面板提示或现象 | 处理方式 |
| --- | --- |
| 请打开并保留官网标签页 | 打开同一浏览器配置文件中的官网并保留标签页，完成登录后点击「立即同步」 |
| 请刷新已登录的官网标签页一次 | 更新后原有网页尚未加载新脚本；刷新官网，再点「立即同步」 |
| 官网标签页暂时无法响应 | 激活官网标签页，等它加载完成或正常刷新，再同步 |
| 需要官网登录 | 在同一浏览器配置文件打开官网，完成登录与验证，再点「立即同步」 |
| 官网拒绝访问（HTTP 403）或要求网页验证 | 在官网标签页检查提示并正常刷新；若官网请求仍被拒绝，扩展保留旧结果并退避，不会尝试绕过验证 |
| 请求限流 | 等待面板提示的重试时间；扩展遵守服务器的等待要求，手动同步和暂停 / 恢复不会绕过限流 |
| 断网、接口错误、数据不完整 | 旧结果会标记为待更新；不会把请求失败当作好友集体离线 |
| 状态更新但没有通知 | 先点击「发送测试通知」，再按下方通知排查步骤确认规则、发送状态和系统显示设置 |
| 官网明明已登录，扩展仍无法连接 | 确认版本为 0.1.2，并在重新加载扩展后刷新官网；确认是同一浏览器配置文件，且扩展拥有 vrchat.com 网站访问权限 |

普通访问拒绝、断网或页面中断后，手动重试保留 30 秒节流；仅缺少官网或尚未注入脚本的检查可以在页面就绪后立即重试。服务器限流和明确的等待时间始终优先。

本版本不允许在无痕模式中运行。请在普通浏览器窗口中使用相同的官网会话。反复点击刷新不能让已经过期的登录会话恢复，也不能补齐浏览器没有运行期间的记录。

## 通知排查与测试

1. 点击弹窗或完整面板中的「发送测试通知」。测试不依赖登录或好友变化，即使监控暂停、全局通知关闭，也可以显式试发；这些设置不会被测试改变。
2. 查看最近发送结果。**「浏览器已接受」表示浏览器通知 API 已成功返回通知 ID，不表示操作系统一定弹出了横幅。** 若显示权限被拒绝或创建失败，检查扩展及系统的通知设置后再测试。发送成功会清除之前的失败警告。
3. 如果已接受却没看见，先查看系统通知中心，再到 Windows「设置 → 系统 → 通知」检查 Chrome / Edge 的通知和横幅开关，以及勿扰模式。Windows 可在游戏或全屏时自动启用勿扰，将通知直接放进通知中心。参见 [Microsoft 通知与勿扰说明](https://support.microsoft.com/en-us/windows/experience/notifications-and-do-not-disturb-in-windows)。
4. 测试通知正常后，确认监控正在运行、「桌面通知」已打开，并为目标好友勾选对应的「上线」或「离线」。**只打开全局通知开关，不会自动为全部好友启用提醒。** 通知区会提示当前设置了提醒的好友数量；规则属于当前同步到的账号。
5. 首次成功同步后，再观察一次目标好友的游戏状态变化，等待定时同步或在节流结束后点击「立即同步」。查看动态记录及最近发送结果。网页活跃与离线之间的切换不属于游戏上线 / 离线；首次、过期和恢复基准不会补发之前的变化。

通知沿用静音设置，不播放提示音；Chrome 的 `silent` 选项控制声音 / 振动，不代表关闭横幅。扩展只能报告浏览器 API 的接受或失败结果，无法读取 Windows 的勿扰或横幅开关，也无法确认用户是否看到了通知。参见 [Chrome 通知 API](https://developer.chrome.com/docs/extensions/reference/api/notifications)。

## 本地数据与权限

数据保存在当前浏览器配置文件的 `chrome.storage.local` 中，不使用浏览器账号同步。保存内容包括当前账号与好友的 ID、显示名、状态分类、最近同步时间、提醒规则、有限数量的动态记录，以及重试计划和有限的错误类型 / HTTP 状态码。还会保存最近通知尝试的时间、结果类别、测试 / 好友来源、扩展通知权限类别及最近成功提交时间，用于本地通知排查；这些诊断不包含通知正文、好友身份或原始浏览器错误。最多保留最近使用的 3 个账号的缓存；同步间隔和通知总开关属于扩展全局设置。

扩展不会保存完整的登录接口响应，也不保存密码、验证码、邮箱或 Cookie。它没有第三方分析服务，不上传本地动态记录。完整面板的「动态记录 → 清空」会删除当前账号的历史；移除扩展可删除该扩展的本地存储。

所需浏览器权限：

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存本地设置、状态基准、规则与记录 |
| `alarms` | 安排下一次同步与失败后的重试 |
| `notifications` | 发送你为好友启用的桌面通知及你主动触发的测试通知 |
| `https://vrchat.com/*` | 找到官网标签页，并在官网 `/home` 页面通过隔离脚本读取同源好友接口 |

官网隔离脚本只接受本扩展后台的两类只读操作：当前账号、好友分页。请求使用固定的 `https://vrchat.com/api/1/` 路径、`GET`、`same-origin` 模式及凭据，禁止重定向，不接受任意 URL / 方法 / 请求头。返回数据在网页脚本内先裁剪，后台再校验；一轮同步固定在同一个顶层页面文档中，避免中途导航或切换标签页混入其他结果。

这一设计使用 Chrome 的[内容脚本隔离机制](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)与[内容脚本同源网络规则](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)。不申请 `cookies`、`history`、`scripting` 或所有网站访问权限；仅在官网 `/home` 页面运行随扩展分发的静态隔离脚本。网页不能通过它读取扩展保存的提醒规则或历史记录。

## 开发、离线验证与打包

开发工具要求 Node.js 22 及以上版本，无需安装 npm 依赖。在仓库的 `browser-extension` 目录执行：

```sh
npm run check
npm test
npm run package
```

- `check`：检查 Manifest V3、权限与 CSP、运行时文件引用、模块语法、图标尺寸和敏感内容特征。
- `test`：使用合成账号与网络响应进行离线行为测试，不登录真实 VRChat 账号。
- `smoke`：使用已安装的 Chrome / Chromium 打开实际界面，并注入模拟扩展后台；验证搜索、提醒设置、通知测试按钮与诊断、暂停、清空确认、登录过期的数据隐藏和昵称的安全显示。可选环境变量 `VRC_MONITOR_CHROME` 指定浏览器可执行文件。运行命令为 `npm run smoke`。
- `smoke:session`：真正安装并运行此 MV3 扩展，使用临时浏览器配置和仅本地可达的 HTTPS 官网替身；验证安装前已打开的页面需要刷新、扩展来源请求 403、官网同源请求携带浏览器管理的 HttpOnly / SameSite 会话、完整分页与数据裁剪；还验证测试按钮创建原生通知，以及关闭面板后真实 1 分钟定时器检测上下线、创建对应通知。使用已安装的 Chrome / Chromium 和 OpenSSL，命令为 `npm run smoke:session`；不替换 Chrome API、fetch、时钟或扩展存储。
- `package`：先运行静态检查，再把明确列出的运行时文件与 `LICENSE`、本安装说明打包，生成 ZIP 和 SHA-256 摘要。

输出位于仓库的 `artifacts/packages/`，由 Git 忽略。相同源文件生成相同字节的 ZIP；打包不遍历整个目录，不包含测试、开发脚本、`package.json`、浏览器配置或用户数据。

`Browser extension` 工作流运行上述检查、测试、真实扩展会话烟测、界面烟测与打包，并调用现有 Windows CI，继续执行桌面版构建、离线测试和仓库隐私审计。界面烟测使用临时浏览器配置文件，阻止访问非本地测试地址，不加载真实账号；合成数据截图单独上传为 `vrc-friends-monitor-synthetic-ui-previews`，不混入安装包。界面烟测验证 HTML / CSS / JS 与模拟后台的交互；真实扩展会话烟测另外验证 Chrome 内实际的消息、网络、Cookie 和通知创建行为。它们都使用合成数据，不证明真实 VRChat 账号或当前服务器策略一定可用；无头浏览器中通知创建成功也不证明 Windows 桌面横幅可见，实际账号和系统通知仍需按下列步骤验收。

### 真实浏览器验收

1. 没有官网标签页时加载扩展，确认显示打开官网的提示；打开未登录官网后同步，确认提示正常登录，界面不要求输入密码。
2. 在同一配置文件登录官网并同步，核对当前账号和好友分类；第一次同步不应批量通知。
3. 点击「发送测试通知」，确认最近结果为浏览器已接受，且系统横幅或通知中心能看到测试消息；检查暂停或未勾选好友时仍能独立试发。
4. 为测试好友设置规则，在双方知情的情况下完成一次游戏上线或离线，等待定时同步，核对通知及检测时间；正常连接下再用「立即同步」验证下一次变化，后续定时同步不应重复通知。
5. 暂时断网，确认旧结果标记为待更新；恢复后首次同步不应批量补报。
6. 关闭官网标签页，确认旧结果被标记待更新；重新打开并登录后确认恢复。关闭并重新打开浏览器及官网，确认设置与历史仍在，并能重新同步。
7. 暂停后确认状态不再刷新；恢复后先建立基准。切换官网账号后，确认显示和规则随新账号切换。

提交代码前还应遵循仓库 [贡献指南](https://github.com/UyNewNas/vrc-friends-monitor/blob/main/CONTRIBUTING.md) 与 [隐私检查](https://github.com/UyNewNas/vrc-friends-monitor/blob/main/scripts/Check-Privacy.ps1)。测试、错误报告及截图仅使用合成或已脱敏的数据，不提交真实好友日志、浏览器配置文件或身份凭据。
