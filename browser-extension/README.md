# VRC 好友监控 · 浏览器扩展

这是 `feature/browser-extension` 分支上的 Chromium Manifest V3 版本，适用于 Chrome / Edge 120 及以上版本。目前通过「加载已解压的扩展程序」安装，尚未发布到浏览器扩展商店。

扩展使用同一浏览器配置文件中的 VRChat 官网登录会话，定时同步好友状态。账号密码、验证码都在官网输入。扩展界面不收集密码，也不读取、导出或复制登录 Cookie。

## 安装与第一次使用

1. 获取当前分支的源代码，或下载该分支已通过 CI 的扩展 ZIP 包。
2. 如果使用源代码，安装目录是仓库中的 `browser-extension`。如果使用 `VRC-Friends-Monitor-*-chromium.zip`，先解压，安装目录是直接包含 `manifest.json` 的文件夹。
3. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`，开启「开发者模式」。
4. 点击「加载已解压的扩展程序」，选择上一步的安装目录。不要选择仓库最外层目录，也不要直接选择 ZIP 文件。
5. 在这个浏览器、这个用户配置文件中打开 [VRChat 官网](https://vrchat.com/home)，正常登录并完成官网要求的验证。
6. 点击工具栏的扩展图标，再点击「打开完整面板」。若显示需要登录，完成官网登录后点击「立即同步」。
7. 在好友列表里为需要关注的人勾选「上线」和 / 或「离线」，确认「桌面通知」已打开，并允许系统显示浏览器通知。

初次成功同步用于建立状态基准，不会把当前在线的全部好友报成「刚上线」。随后在正常定时同步中检测到的游戏状态变化才会记入动态记录，并按你勾选的规则提醒。

使用源代码安装无需 Node.js，也无需运行构建命令。请保留安装目录；浏览器会继续从这个目录加载文件。更新源代码或替换解压内容后，到扩展管理页点击该扩展的「重新加载」。

### 获取并核对 CI 安装包

在仓库 GitHub Actions 中打开对应提交的 **Browser extension** 工作流，确认扩展检查与 Windows 兼容性检查通过，再下载 `vrc-friends-monitor-chromium` artifact。GitHub 下载的 artifact 外层 ZIP 中包含扩展 ZIP 及其 `.sha256` 文件；将外层 ZIP 解压后，再解压其中的扩展 ZIP 用于安装。

安装前可核对 `.sha256` 文件中的摘要。Windows PowerShell 示例：

```powershell
Get-FileHash .\VRC-Friends-Monitor-0.1.0-chromium.zip -Algorithm SHA256
Get-Content .\VRC-Friends-Monitor-0.1.0-chromium.zip.sha256
```

两处 SHA-256 应一致。文件名中的版本号以实际下载内容为准。摘要用于核对文件是否改变；来源仍应是你选定的仓库、分支和提交。

## 监控行为

| 项目 | 当前行为 |
| --- | --- |
| 状态同步 | 默认每 1 分钟；完整面板可改为每 2 或 5 分钟 |
| 好友昵称目录 | 首次同步时加载，之后约每 10 分钟刷新 |
| 游戏在线 | 好友当前处于 VRChat 游戏在线状态 |
| 网站活跃 | 官网报告的非游戏客户端活跃状态（例如网站），单独显示，不计作游戏上线 |
| 游戏上线提醒 | 从非游戏在线变为游戏在线时，按好友的「上线」规则通知 |
| 游戏离线提醒 | 从游戏在线变为非游戏在线时，按好友的「离线」规则通知；好友此时仍可能显示网站活跃 |
| 动态记录 | 正常同步时记录检测到的游戏上下线变化；每个账号最多保留最近 1,000 条 |
| 暂停监控 | 点击「暂停监控」后停止自动请求，仍可手动同步；点击「开启监控」后重新建立基准 |
| 账号切换 | 以官网下一次成功同步识别的账号为准；好友规则和历史记录按账号分开 |

动态记录的时间是扩展**检测到变化的时间**。它不是 VRChat 提供的精确登录或退出时间；两次同步之间短暂上线又离线的变化可能被漏过。

首次同步、手动「立即同步」、重新登录、账号切换，以及断线或较长延迟后的恢复同步，会更新状态基准，不会补报期间的上下线变化。这样可避免恢复后一次性弹出旧通知。好友新增、删除也不会伪装成游戏上下线事件。

关闭弹出窗口或完整面板后，后台仍可按计划同步。**浏览器完全退出后无法监控；电脑休眠、断网、浏览器节能或后台调度延迟都可能造成空档。** 官网会话也可能过期，需要回官网重新登录。浏览器扩展改善了登录入口与后台恢复方式，不提供永久在线或实时无遗漏的保证。

## 连接异常时

| 面板提示或现象 | 处理方式 |
| --- | --- |
| 需要官网登录 | 在同一浏览器配置文件打开官网，完成登录与验证，再点「立即同步」 |
| 官网拒绝访问或要求网页验证 | 打开官网查看提示；扩展会保留上次成功结果并延后重试 |
| 请求限流 | 等待面板提示的重试时间；扩展遵守服务器的等待要求，手动同步和暂停 / 恢复不会绕过限流 |
| 断网、接口错误、数据不完整 | 旧结果会标记为待更新；不会把请求失败当作好友集体离线 |
| 状态更新但没有通知 | 检查全局「桌面通知」、该好友的上线 / 离线勾选，以及浏览器和操作系统通知设置 |
| 官网明明已登录，扩展仍无法连接 | 确认不是另一个浏览器、另一个配置文件或无痕窗口中的会话；查看扩展管理页是否禁用了扩展所需的网站访问权限 |

本版本不允许在无痕模式中运行。请在普通浏览器窗口中使用相同的官网会话。反复点击刷新不能让已经过期的登录会话恢复，也不能补齐浏览器没有运行期间的记录。

## 本地数据与权限

数据保存在当前浏览器配置文件的 `chrome.storage.local` 中，不使用浏览器账号同步。保存内容包括当前账号与好友的 ID、显示名、状态分类、最近同步时间、提醒规则、有限数量的动态记录，以及重试计划。最多保留最近使用的 3 个账号的缓存；同步间隔和通知总开关属于扩展全局设置。

扩展不会保存完整的登录接口响应，也不保存密码、验证码、邮箱或 Cookie。它没有第三方分析服务，不上传本地动态记录。完整面板的「动态记录 → 清空」会删除当前账号的历史；移除扩展可删除该扩展的本地存储。

所需浏览器权限：

| 权限 | 用途 |
| --- | --- |
| `storage` | 保存本地设置、状态基准、规则与记录 |
| `alarms` | 安排下一次同步与失败后的重试 |
| `notifications` | 发送你为好友启用的桌面通知 |
| `https://vrchat.com/*` | 通过官网接口入口请求好友状态 |
| `https://api.vrchat.cloud/*` | 跟随官网接口的重定向访问 VRChat API |

请求由官网使用的 `https://vrchat.com/api/1/` 入口发出；官网可能将其重定向到 `api.vrchat.cloud`。浏览器按自身 Cookie 规则处理每个域的已有会话，扩展不把一个域的 Cookie 手动复制到另一个域。若浏览器策略或会话状态使请求无法通过，应回到官网正常登录和验证。

不申请 Cookie、浏览历史读取、网页脚本注入或所有网站访问权限。所有可执行脚本都随扩展一起分发。

## 开发、离线验证与打包

开发工具要求 Node.js 22 及以上版本，无需安装 npm 依赖。在仓库的 `browser-extension` 目录执行：

```sh
npm run check
npm test
npm run package
```

- `check`：检查 Manifest V3、权限与 CSP、运行时文件引用、模块语法、图标尺寸和敏感内容特征。
- `test`：使用合成账号与网络响应进行离线行为测试，不登录真实 VRChat 账号。
- `smoke`：使用已安装的 Chrome / Chromium 打开实际界面，并注入模拟扩展后台；验证搜索、提醒设置、暂停、清空确认、登录过期的数据隐藏和昵称的安全显示。可选环境变量 `VRC_MONITOR_CHROME` 指定浏览器可执行文件。运行命令为 `npm run smoke`。
- `package`：先运行静态检查，再把明确列出的运行时文件与 `LICENSE`、本安装说明打包，生成 ZIP 和 SHA-256 摘要。

输出位于仓库的 `artifacts/packages/`，由 Git 忽略。相同源文件生成相同字节的 ZIP；打包不遍历整个目录，不包含测试、开发脚本、`package.json`、浏览器配置或用户数据。

`Browser extension` 工作流运行上述检查、测试、界面烟测与打包，并调用现有 Windows CI，继续执行桌面版构建、离线测试和仓库隐私审计。界面烟测使用临时浏览器配置文件，阻止访问非本地测试地址，不加载真实账号；合成数据截图单独上传为 `vrc-friends-monitor-synthetic-ui-previews`，不混入安装包。它验证实际 HTML / CSS / JS 与模拟后台的交互；已安装扩展的官网会话、网络访问和系统通知仍需按下列步骤验收。

### 真实浏览器验收

1. 未登录官网时加载扩展，确认显示需要登录，界面不要求输入密码。
2. 在同一配置文件登录官网并同步，核对当前账号和好友分类；第一次同步不应批量通知。
3. 为测试好友设置规则，在双方知情的情况下完成一次游戏上线或离线，等待定时同步，核对通知及检测时间。
4. 暂时断网，确认旧结果标记为待更新；恢复后首次同步不应批量补报。
5. 关闭并重新打开浏览器，确认设置与历史仍在，并能重新同步。
6. 暂停后确认状态不再刷新；恢复后先建立基准。切换官网账号后，确认显示和规则随新账号切换。

提交代码前还应遵循仓库 [贡献指南](https://github.com/UyNewNas/vrc-friends-monitor/blob/feature/browser-extension/CONTRIBUTING.md) 与 [隐私检查](https://github.com/UyNewNas/vrc-friends-monitor/blob/feature/browser-extension/scripts/Check-Privacy.ps1)。测试、错误报告及截图仅使用合成或已脱敏的数据，不提交真实好友日志、浏览器配置文件或身份凭据。
